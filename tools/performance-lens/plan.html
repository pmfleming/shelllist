1. Recommended direction

Implementation update: the standalone Rust CLI now provides passive resource capture, supported DRM counters, consent-gated warm-open trials, offline reports and descriptive comparisons. See README.md for commands, validation and remaining scope. This document preserves the original broader plan; cold-session automation, richer visual latency and automatic regression gates are not implemented.
Observe, do not embedA standalone Rust binary attaches to an explicitly identified Quickshell instance and samples Linux counters. Existing IPC supplies narrowly scoped timing observations.
Start with useful baselinesMeasure popover-hidden idle, one visible surface, and repeated warm opens. Separate the UI host, bridge clients and independently managed daemons.
Keep evidence honestMissing GPU support stays unavailable. Qt frame swap is not input-to-photon. Cold QML loading is not cold storage or backend readiness.

Build a new, small tool at shelllist/tools/performance-lens/. Borrow the sibling Scratchpad lens’s evidence discipline, not its editor-specific producer catalog. Implement collection, orchestration, statistics, comparison and HTML generation in Rust. Reports use static HTML/CSS and inline SVG: no JavaScript, Node, browser automation framework, server or CDN.

First deliverable: one passive 60-second capture of the running Shelllist instance, with CPU/RSS/I/O timelines, explicit process scope, optional PSS and supported GPU counters, plus a self-contained report. Then add consent-gated warm-open timing and controlled baseline comparisons.

Use one binary, provisionally shelllist-perf, with doctor, capture, run, report and compare commands. A small synchronous sampling loop plus bounded subprocess workers is sufficient; no async runtime or plugin framework initially. Start with clap, serde/serde_json, toml, an error crate, a hashing crate, and a small Linux API dependency for clock ticks/process handling. Use tempfile for tests. Lock dependencies; keep procfs/DRM parsing behind fixture-tested modules.

  • No production dependency: no Shelllist workspace membership, runtime imports, QML hooks, daemon changes, root flake integration or application packaging changes. Use the existing Rust toolchain and cargo --manifest-path; build the lens and application before collecting. Removing the directory must leave Shelllist behavior/build unchanged.
  • Passive default: capture reads OS counters only. It neither launches Shelllist nor opens/hides a panel. doctor reports discovery and permissions without activating services. Target-session IPC checks are explicit.
  • Resolve identity, not a name substring: accept an explicit PID or resolve the exact user-service cgroup and Quickshell config path/instance. Record boot ID, PID, start ticks, UID and executable. Refuse ambiguous instances; detect PID reuse and restarts. Do not assume the service MainPID is always the renderer.
  • Prefer instance-targeted IPC: capability-check the installed Quickshell CLI and route to the verified instance. Do not rely blindly on --newest. Record exact executable/config paths. Keep public-wrapper command timing separate from direct IPC timing.
  • Beware automatic host replacement: the packaged wrapper’s ensure_daemon() can call stop_stale_hosts(). The lens must not invoke launch-capable wrapper commands against an absent/mismatched host. Abort on target loss; never turn a benchmark into an implicit restart or deployment.
  • Active tests require consent: --allow-ui-control is required to open/hide surfaces. Begin with no visible popover; abort rather than closing someone’s unsaved draft. Hide only the surface opened by the run, and stop if the user changes it. Restore focus only when safe; do not kill/restart user services for cleanup.
  • Cold tests are a separate session: a nested compositor or dedicated test login must first prove safe service/config routing. Separate XDG directories alone do not isolate shared D-Bus daemons or global shortcuts. Do not start a duplicate bar in the normal desktop or reset caches/settings to manufacture a cold run.
  • Read-only domain behavior: no Wi-Fi connection, Bluetooth pairing, volume changes, notification dismissal, updates, power actions or display preview. Opening a surface may naturally request data or discovery; record that workload. Default reports omit clipboard text, notifications, device identifiers and window titles.
No panel work is proposed. Existing navigation, draft/commit behavior, acknowledgements and safety guards remain untouched. If later requirements truly demand instrumentation or panel changes, treat that as separate scope with the project’s panel contracts and actual Qt interaction tests—not a hidden prerequisite of this lens.

4. Resource measurements and attribution

Sample lightweight process counters every 250 ms; PSS and GPU discovery/counters every 1 second initially. Use actual monotonic intervals and report collection duration, missed deadlines and gaps. Allow slower rates for low-overhead idle runs.

MetricSource / calculationMeaning and limits
CPU/proc/PID/stat user + system ticks: 100 × Δticks / CLK_TCK / Δseconds.CPU seconds, time-weighted phase average and sampled peak. 100% = one logical core; values can exceed 100%. Threads are already included. Never add child accounting fields to independently sampled child processes.
Memorystatus: VmRSS, VmHWM, threads; smaps_rollup: PSS/private memory when permitted.Baseline/end RSS, sampled peak, PSS and post-cycle retained growth. VmHWM is process-lifetime, not phase peak. RSS is not heap allocation traffic; sum-of-RSS is not unique physical memory. Sampled peaks can miss short bursts.
I/O/proc/PID/io: read_bytes/write_bytes, rchar/wchar, syscall counts; stat: minor/major faults.Phase deltas and rates. Storage-accounted bytes stay separate from syscall character traffic, which can include IPC. Cached/mapped access may not appear as disk reads. Buffered writes are not fsync durability or storage latency; these are not network byte counters.
GPU enginesCapability-detected /proc/PID/fdinfo/* DRM engine counters; identify device, client ID and engine/capacity metadata.Per-engine busy-time deltas; utilization only with known units/capacity semantics. Deduplicate shared/duplicated DRM clients by device + client ID across descriptors and processes. Keep non-additive engines separate; no fabricated universal GPU percentage.
GPU memorySupported DRM region memory/resident/shared counters.Preserve driver-defined field meaning and units; distinguish allocation from residency. Shared/integrated memory may overlap RSS. Do not add CPU and GPU memory into a misleading total.
Host contextCPU/GPU model, kernel/driver, Qt/Quickshell/compositor versions, outputs/scale/Hz, power mode, host load; observed render backend if available.Comparison context, not attribution. Any optional device-wide GPU counter is labelled system-wide, including compositor and other apps. Missing per-process GPU support remains unavailable, never zero.
Lens overheadLens CPU/RSS, helper-process usage where available, sample duration, IPC command count and polling cadence.Show observer cost separately. Responsiveness polling produces real work in the target; do not subtract an assumed correction. Separate quiet resource captures from polling-heavy timing runs.

Three explicit process scopes

  1. UI host: the verified Quickshell process, including bar, popover and its threads. “Hidden” means the popover is hidden; the bar still exists and may animate/update.
  2. UI service scope: exact cgroup membership, including bridge clients; preserve per-process rows and identify restarts. Optional cgroup-v2 CPU/memory/I/O counters offer a separate service-scope view, not values to add on top of procfs totals. Cgroup memory includes accounting beyond process RSS.
  3. Related daemons: explicitly configured/resolved app-daemon, nm-daemon, bt-daemon, clip-daemon and bar-daemon, each in its own scope. They may serve other clients. Call their measurements “related daemon activity,” not exclusively Shelllist-caused cost. Never activate an absent daemon just to monitor it.

Discover service membership periodically, without scanning all of procfs on every tick. First observations have no delta. Permission loss, process exit, negative/reset counters, disappeared GPU clients and unsupported fields yield null with a reason. Short-lived processes can escape polling: disclose coverage gaps, and prefer service cgroup accounting when available. Do not extend a last-known value across missing intervals.

5. Responsiveness: use what exists, label it precisely

Shelllist exposes status, listSurfaces and responsiveness through its existing IPC. These are sufficient for an initial open-path lens without adding code to the UI, but not for end-to-end input latency.

MetricStart → stopAllowed interpretation
Command acknowledgementRust monotonic time immediately before spawning the selected command → successful process exit and valid reply.Public wrapper round trip includes shell/Quickshell discovery, IPC and scheduling. Direct targeted IPC is a different series. Neither is time to usable content.
Open → Qt frame-swap callbackPopupWindowHost.showPopover() sets Date.now() → onFrameSwapped records the first callback.UI-side open-to-first-callback proxy. Starts after earlier command/selection work; callback delivery and wall-clock resolution affect it. Not compositor presentation, complete content, FPS or physical input-to-photon.

Trial protocol

  1. Verify target identity and hidden state; snapshot opened/loaded and the latest timing record. Resolve supported surfaces from the exact target’s catalog.
  2. Issue one open; measure the chosen command path. Reject invalid replies, wrong surfaces and host replacement. Poll existing timing IPC at a documented bounded rate, initially 25 ms, with a 3-second configurable timeout.
  3. Require a new open timestamp, matching surface, valid first-frame timestamp and, for first-open loading, a fresh matching content record. Archive before/after records and poll observations. The API has no unique request ID: serialize actions, enforce spacing, and invalidate ambiguous/concurrent trials.
  4. Only hidden-to-visible opens refresh the frame timing. Already-visible surface switches must not reuse that value. Keep frame and content endpoints separate; either may arrive first.
  5. Record failures/timeouts before cleanup. Hide only if the run still owns that UI interaction, allow 250 ms settling, and repeat. Abort on unexpected user activity or service restart.

Rust durations use Instant. Existing QML values use millisecond wall time; preserve that source and precision, do not subtract them from Rust timestamps. Detect wall-clock discontinuities against monotonic elapsed time where possible and invalidate affected trials. A native zero can be quantization, while a warm-content zero is a programmed sentinel; neither establishes instantaneous rendering.

True backend-result readiness, typing latency, animation jank, dropped presented frames and GPU frame time are not covered by the initial IPC contract. Add a separately validated external observation method later, or explicitly leave them unmeasured. Low CPU does not prove a responsive event loop.

7. Baselines, evidence and reports

Statistics and comparison rules

  • Collect three independent resource runs per condition. For response actions show all raw trials, count, median, maximum and failures. At 30 trials, nearest-rank p95 is descriptive and noisy; suppress p99 initially. Repeated actions in one host are not independent process launches.
  • Report successful-trial latency separately from timeout/error counts and censoring limits. A fast median never hides a failed trial. Use time-weighted CPU/rate averages; resource samples are not independent latency trials.
  • First measure variability, then set human-approved budgets in TOML. Existing scripts’ defaults—2% of one core, 300 MiB PSS, 50 ms acknowledgement, 100 ms warm frame and 300 ms cold content—are historical reference points, not automatically adopted gates.
  • Compare the same host, scope, scenario/workload, display/backend, sampling method, command path and versions of metric definitions. Record all mismatches; block automatic regression verdicts for incompatible contexts. Candidate application identity may differ by design; daemon/framework revisions must be matched or the comparison labelled whole-stack.
  • Use alternating A/B runs when comparing builds, with no builds during capture. Require an absolute noise floor as well as a relative change threshold. Near-zero baselines use absolute deltas only. Initial reports are descriptive, not statistical-significance claims.
  • Keep historical baselines instead of copying the sibling lens’s automatic 24-hour expiration. Show age/context clearly; an old baseline describes the old build, not certification of the current executable.

Typed artifact contract

Every metric carries id, unit, scope, source, nullable value and availability reason. Separate run completeness (complete / partial / failed) from optional budget assessment (within / above / uncertain / unmeasured). Unsupported GPU data need not fail a resource capture, but cannot pass a GPU budget.

The manifest records schema version, run ID, UTC time, monotonic origin, lens binary hash/version, target PID/start time/boot ID, resolved Quickshell binary and QML config identity, packaged store paths or source hashes, wrapper path/hash, relevant daemon identities, source revision/dirty fingerprint when available, allowlisted environment, host/display context, scenario hash, collector capabilities, command/poll cadence, exit status and interruptions. A Git checkout revision alone does not identify the deployed QML or daemon binaries.

Write samples/events incrementally as JSONL, preserving raw counters and action endpoints. Finalize summaries/reports atomically and bind them to raw-file hashes. Validate schema, finite values and unit consistency; truncated files remain explicitly partial, never silently successful. Cap diagnostic log size, use unique run directories and do not overwrite selected baselines.

One offline report

Generate five clear sections: responsiveness, CPU, GPU, memory and I/O. Show scope selectors as separate static sections/tables, phase-aligned SVG timelines, per-process breakdowns, baseline deltas and failure counts. Put capability gaps and measurement boundaries near the affected metric. Include a source/provenance appendix and links to raw files. HTML-escape labels/logs; no scripts or network assets. The report must work directly through file://.

9. Acceptance checklist

  • Separation: production QML/Rust/TypeScript, daemon code, manifests and packaging remain unchanged. Lens runtime and report generation require no JavaScript or Python.
  • Targeting/safety: Rust integration tests cover multiple Quickshell instances, PID reuse, absent service, host restart, ambiguous config, already-visible draft, user interruption and Ctrl-C. No unrelated process is stopped; active runs fail closed if routing cannot be verified.
  • Correct counters: fixtures cover proc names containing spaces/parentheses, tick/KiB units, missing fields, permission errors, counter resets, process churn, duplicate DRM clients, unsupported engine capacities and device changes. Cross-check scoped CPU/memory/I/O with known workloads and an independent tool.
  • Honest timing: fake IPC fixtures cover stale timestamps, warm-content zero, first-frame-before-content, content-before-frame, wrong surface, timeouts, malformed JSON, clock discontinuities and visible-to-visible switches. Every attempted trial is represented.
  • Live validation: run passive captures before active scenarios; compare selected raw existing IPC values with Rust artifacts in a consenting session. No Qt interaction tests are needed for unchanged application code; any later application behavior changes require them separately.
  • Low overhead: measure lens plus helper cost and compare slow/default sampling rates. Initial engineering target: sampler below 1% of one core in settled passive capture. This is a target to verify, not a result. Flag late samples; reduce cadence if overhead is material.
  • Artifacts: tests reject corrupted/truncated evidence as complete, preserve partial failures, check incompatible baselines and HTML escaping, and verify reports contain no scripts or external dependencies. Keep output bounded and selected baselines safe from pruning.
  • Baseline usefulness: three idle captures and 30 warm-open attempts per selected surface establish the first descriptive baseline. GPU support, UI versus daemon scope, QML-load semantics and unmeasured responsiveness categories remain visible.
Definition of done: one Rust command captures an explicitly identified Shelllist session and produces a trustworthy local resource report; a second opt-in scenario adds open-path responsiveness. The tool lives with Shelllist, but Shelllist does not depend on it.
