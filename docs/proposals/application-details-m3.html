01 · Application details

Material 3 · Desktop adaptation

Less chrome.
More useful context.

One template for every installed application—and whatever comes next. Render the capabilities the catalog actually reports: return to a window, launch an app, or invoke its own named actions. Never assume every app is a browser.

01 / VISUAL HIERARCHY

Everything asks for attention

The outlined window, large repeated circles and visible desktop behind the text compete. Use opaque tonal content surfaces, fewer borders and consistent spacing. Rounding alone does not make a screen M3.

02 / ACTION CLARITY

Three different actions, one play icon

Use each desktop action’s icon when available, with a neutral execute fallback when it is not. Keep the app-provided names beside the circles. Separate returning to a window from closing one.

03 / USEFUL INFORMATION

Location matters more than CPU

Lead with the full window title, workspace and explicit current-window status. Put resource telemetry in the existing Resources page, where attribution and history can be explained.

A

One unmistakable primary

The existing identity header gets one filled 56px command: return to the most recent window, or launch when not running. No competing filled actions.

B

Windows, not “instances”

A grouped list replaces individually outlined pills. Keep the real title—including “(121)”—and label the workspace. “Current window” comes from compositor state, not pointer hover.

C

Make close deliberate

Keep a focus-window circle; move Close into a named per-window menu. No ambiguous × beside the everyday action. Do not imply that a closed browser window can be undone.

D

Recognizable, compact commands

Render zero, one or many desktop-defined actions, keeping their localized names and IDs. Resolve supplied icons; otherwise use a neutral execute glyph. Never guess behavior from the app name. Labels stay passive.

Recommended scope: presentation and discoverability only. No new backend capability, keyboard variant, “close all”, forced quit or invented memory-health warning.

A failure is not a dismissal

Keep the chooser open, retain the target and explain the failed operation. Offer retry only for known failures; refresh uncertain outcomes rather than replaying them.

Material, not just rounded

  • Color roles: opaque content containers; on-surface text; primary only for priority. This hand-picked green study is illustrative—production uses the existing seed-derived Ui.MaterialPalette, not these hex values.
  • Type & spacing: production Roboto Flex; 24/16/14/12px hierarchy, 8px rhythm, 24px between groups, 16px inset. This offline HTML uses local system-font fallbacks and embedded SVGs.
  • Shape & targets: 28px panel, 16px list groups; 56px primary, 32px header secondary, 48px contextual circles. These follow Shelllist’s desktop adaptation, not a claim of exact M3 certification.
  • Accessibility: retain full accessible command names and status text, not color alone. Validate contrast with the generated theme, scaling, native focus paint and assistive technology in Qt.

Capability-driven, not browser-driven

  • Any installation: consume the daemon’s XDG catalog identity, localized name, icon, kind, windows and desktop-action list. Refresh on catalog changes. No frontend app allowlist or per-application layout registry.
  • Unknown is normal: generic icon for unresolved assets; wrap long titles and translated labels; hide empty action groups. Bound long lists with scrolling and retain every action in Alt+J. Shortcuts expose launch only, not invented window/resource state.
  • Illustrative data only: editor, terminal, file manager, future-app and shortcut fixtures demonstrate structure—not verified installed apps or exact desktop-entry capabilities. Browser privacy/profile commands exist only when that app actually supplies them.
  • No new field stops: titles, telemetry and command rows are information-only. Tab visits editable controls; command-only pages use the shared scrolling fallback. Up/Down still browse application results.
  • Commands: use shared SurfaceActionRow, LabeledAction and ActionMenu. Arbitrary desktop/per-window commands remain under Alt+J; reserve Alt+M for existing header overflow and Alt+S for screenshots.
  • Honest data: do not add per-window CPU numbers unless the daemon provides reliable attribution. Preserve unknown workspace labels and capability guards. Hide absent desktop actions; do not invent browser features.
  • Safe operations: keep revision checks, in-flight guards and terminal acknowledgements. A focus/launch success closes the real chooser; close updates in place. A submitted request alone never means success.
  • Ship with Qt tests: cover named window/desktop commands, stale targets, menu focus restoration, in-flight disabling, failures, zero/many windows and long titles. This HTML is a proposal, not production interaction validation.
