One line.
Not three.

Take the search box’s best idea: purpose on the left, content in the middle, useful actions on the right. Give ordinary fields the same economy—and make read-only impossible to miss.

01 / The recommendation

Flatten the layout, not the meaning.

Remove the permanent label above and helper line below. Keep a semantic icon and, where the icon alone is ambiguous, a short inline name. Use a visible lock badge instead of “Automatic · read-only” in tiny text.

02 / Three directions

How far should the label disappear?

All three remove the routine above/below text. The difference is how much meaning the icon must carry.

A / COMPACT LABELLED ROW

The best general default.

Icon + short inline name + value + relevant actions. Almost as compact as search, without asking people to learn a pictogram vocabulary.

03 / More than a smaller rectangle

Make the state visible, not verbose.

Purpose, editability and operation status are separate signals. Don’t make one tiny footer explain all three.

01 · Editable / idle

NameStudio headphones

Filled input surface. No lock and no permanent pencil button: Enter or pointer entry already starts editing.

02 · Browsing / keyboard target

NameStudio headphones

A tonal highlight and opaque marker identify the editable area only. Not the icon, label or entire row.

03 · Editing / local draft

Stronger edge + native caret. Enter saves; Escape discards; Tab saves and continues editing. No extra save/cancel button pair.

04 · Read-only / still useful

NameStudio headphones

Lock + different surface, not faded text. No edit baseline, caret or field Tab stop. Copy and text selection remain available where safe.

Only useful commands: browse for a path, reveal for a password. Do not add Copy, Clear, Help and Reset everywhere. Secrets do not gain automatic copy commands or presentation-memory storage.

Where did the helper text go?

Routine guidance moves to an explicit, named Help command, not a hover tooltip. For example: “IPv4 prefix length: 0–32. Gateway: optional. DNS: comma- or whitespace-separated addresses.” Errors, security warnings and required recovery instructions stay visible where needed. This disclosure illustrates the information hierarchy, not a new panel keyboard model.

05 / Design rules

Less chrome. No guessing.

01 / PURPOSE

Icon first, not icon only.

Use a shared semantic vocabulary. Keep a short inline name for ambiguous fields. Full translated names belong in accessibility and named commands; no new hover tooltips.

02 / READ-ONLY

A lock you can see.

20px lock in a 32px rounded-square badge. Passive, not clickable. Keep values readable; remove editing affordances. Do not imply that pressing the lock can override policy.

03 / ACTIONS

Useful, not ornamental.

32px command circles, 16–18px icons. Usually zero or one command, at most two. Stable hit areas; domain guards remain authoritative. Status badges are not buttons.

04 / DENSITY

One 52px row.

Proposed shared compact token: 52px minimum height, 16px corners, 12px side padding, 10px between rows. Scale with uiScale. Do not hard-code a smaller local variant per panel.

05 / WIDTH

Let content win.

Keep type and action targets stable. Stack address/prefix at narrow widths; allow labels to wrap when translation requires it. Native editors scroll horizontally; read-only elision must retain full copy/inspection.

06 / EXCEPTIONS

Words where they help.

No reserved helper row at rest. Validation, failures, safety instructions and genuinely multiline text may expand. Space-saving must never conceal the reason a setting cannot be applied.

06 / If adopted

Change the composition, not the key model.

This revises the earlier form-field proposal’s external-label/support-row direction. It is not approval to replace native editors or weaken the shared interaction contract.

Selected direction: C as the general default. Keep A’s inline identity and useful actions without its filled resting container. Reserve B for purposes that truly need no label. The biggest improvement is not the radius—it is removing the two routine text rows and making read-only a first-class visual state.
