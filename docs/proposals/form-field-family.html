01 / Design direction

Similar materials. Different silhouettes and semantics.

Borrow from search

Opaque semantic surfaces, 16px native text, generous side padding, comfortable embedded actions and immediate feedback.

Keep forms distinct

12px rather than capsule corners; persistent labels; validation and acknowledgement; optional units; no magnifier unless the field actually searches.

Do not change ownership

Qt owns editing and IME. FieldEditSession owns the local transaction. Domains own validation, draft recovery, backend requests and acknowledgement.

Choose one filled default across a form region, including its selectors. Do not mix outlined text inputs with filled dropdowns merely because different components were migrated first. Keep an outlined region-level fallback available only if a contrast/accessibility review requires it—not as a per-panel styling preference.

The original outlined fields are not “non-Material.” Material supports both variants. The proposed change deliberately favors the filled variant to match SheLLList’s current search, tonal cards and expressive visual direction.

Layout cost is explicit: a 56px editor plus its label and a reserved supporting row is taller than today’s compact field. Use the existing detail scrolling and better grouping, not smaller type, clipped messages or a larger popover imposed without approval.

Labels and actions

  • Required fields use a consistent marker and one short form-level explanation; optional fields are identified consistently.
  • A placeholder is an example, never the sole name and never a pre-filled value.
  • Use leading icons only when they convey input semantics. Do not add a decorative icon to every setting.
  • Clear, reveal, apply and send actions keep explicit accessible names, availability guards and existing command routing.

Accessibility composition

  • Forward the visible label to the native editor’s Accessible.name; do not leave Wi-Fi credentials named merely “Required” or “Optional.”
  • Associate units, required/read-only state and relevant supporting/error text through supported Qt semantics.
  • Do not let a wrapper replace the native editable role with a generic grouping/button.
  • Verify actual Qt announcements. HTML ARIA examples are guidance, not QML APIs.
04 / Interaction & states

A visual family must distinguish three different truths.

Focus says where input goes. Validation says whether a draft is usable. Acknowledgement says whether a backend accepted a request. Do not conflate these with one green/red outline.

  • Hover: subtle decoration only. Never move selection, reveal explanations, open tooltips or start editing.
  • Browse: retain the existing immediate 8% tint plus contrast-qualified opaque marker. Paint only the editable area, not its external label or supporting row.
  • Edit: retain the stronger tint/edge and native caret/selection. No new delayed focus motion or second focus ring.
  • Read-only: no field Tab stop, but normal value contrast and native text selection where supported. An explicit copy command, if needed, must be reachable without first browsing a non-editable field.
  • Disabled: show unavailability, not a fake empty value. Keep necessary capability/failure explanations readable even if control decoration is subdued.
  • Pending/failure: keep domain acknowledgement, rejected drafts, retry/discard and unknown outcomes authoritative. Do not clear a draft or show “Saved” because Enter was pressed.

Error timing recommendation: preserve the parser’s Invalid / Intermediate / Acceptable states. Do not present an unfinished 192.168.1. as a failure on every keystroke. On an explicit save attempt, explain incomplete or invalid input inline. Once an error is exposed, update or clear it as the draft is corrected. Keep useful range/format information persistent, not focus-triggered help.

05 / IP and DNS are not ordinary numbers

One address, one native editor.

IPv4 / IPv6 address

  • Use a native text editor, not a number control, four octet widgets or eight hextet widgets.
  • Preserve selection, Home/End, cursor arrows, clipboard operations, IME and single-line horizontal scrolling.
  • IPv4 accepts dotted notation; IPv6 keeps compression, hex, and supported embedded IPv4. Do not auto-insert separators or auto-advance focus.
  • Use advisory input hints, never a digits-only restriction for an address. Verify that virtual keyboards can enter ., : and hex characters in the relevant family.
  • Do not change leading-zero, canonicalization or routability policy in a styling migration. Existing validators and daemon validation remain authoritative.

Prefix length / gateway

  • Prefix remains its own field: 0–32 for IPv4, 0–128 for IPv6. Digits-only hints are appropriate here.
  • Its accessible identity is “IPv4/IPv6 prefix length,” including the range—not just “/”.
  • Gateway uses the same address editor, with empty allowed where currently supported.
  • Do not invent subnet masks, address discovery, subnet-membership warnings, reachability checks or a new routing capability.
  • Automatic values remain visibly read-only. Switching to manual editing must retain current draft/acknowledgement policy.

DNS servers and search domains

Keep one native list editor. Support the existing comma/whitespace delimiters, retain order, and do not silently deduplicate. For long IPv6 lists, use a two-line text-area variant with native scrolling rather than removable chips. It is one field transaction: Enter/Tab saves, Shift+Enter inserts a newline. The current parser/payload split already recognizes whitespace; the multiline adapter still needs real interaction tests.

DNS server validation stays family-specific. Search domains remain a distinct text-list field, not IP addresses; do not reuse the IP validator or introduce a new hostname grammar without a domain decision. Explanations should identify the failing address/token where the validator can support that precisely.

Important paste boundary: do not silently truncate into a valid address

Current address editors have maximumLength 15/45, while the validator checks the text it receives. A native paste such as 192.168.100.100/24 can lose the suffix under a tight IPv4 length limit before validation. The implementation must reproduce and cover this boundary.

Recommended phase 1: keep CIDR as invalid in the address field and explain the separate prefix input; do not strip or split it automatically. Separate the semantic accepted-address length from the bounded transient editing buffer so malformed pasted suffixes remain visible to validation. Test every supported paste/input route; do not add a keyboard-only paste interception that misses pointer paste or IME.

Defer: automatic CIDR splitting. It affects two drafts and needs atomic save/discard, family/range checks and acknowledgement semantics; it is not a decorative field feature.

06 / Semantic variants

Shared presentation, specialized native behavior.

Names, labels and short text

Normal 56px field; existing trim/length validation. Bluetooth device and adapter names should no longer differ solely because one hardcodes 38px. Preserve pending rename, original-name restoration and retry/discard.

Secrets and pairing codes

Native password echo, selection/IME and sensitive classification. Reveal stays explicit with “Show/Hide password” names. No secret in view memory, logs, screenshots or automatic counters. Dialog closure clears credentials as before.

Numbers with units

Separate display suffix from the editable value. Use a digits/decimal hint appropriate to the real domain. Do not introduce steppers or silent unit conversion. Display Focus’s existing numeric validation and guards stay intact.

Choice fields

Restyle DropDownList with the same field shell, type and label composition. Keep native menu navigation, non-selecting hover, draft selection and the distinction between proposed and acknowledged values.

Multiline content

Shared padding, colors, typography, caret/selection and a bounded scrolling viewport. Preserve Clipboard’s lease ownership and failed drafts. Enter/Tab saves; Shift+Enter adds a line; no per-keystroke backend writes.

Inline reply / quick add

Normal field first; 48px compact only if reviewed in the actual toast/Activity layout. Keep 16px text and 48px action targets. Reply sending and todo creation remain explicit commands, not accidental consequences of visual reflow.

Use measured minimum value widths, not a universal two-column breakpoint. For the address/prefix pair, reserve roughly 112–128px for prefix and enough room for useful address editing; stack before either becomes cramped. Long single-line values scroll with the caret. Long errors may wrap. Validate labels in translation instead of hiding their ends.

07 / Engineering boundaries

Evolve the shared controls. Do not fork the keyboard model.

  1. Theme tokens: add named form height/radius/value/label/support/slot tokens. Keep search tokens separate so a form migration cannot silently reshape search.
  2. FieldFrame: provide the filled paint, native-input padding/slot metrics and existing focus states. Retain an explicit region-level outlined fallback. Avoid a new popover toolkit.
  3. FormField composition: add a passive label + editor slot + supporting/status row. It owns no domain value. The label and help remain outside the focus paint and Tab sequence.
  4. Native adapters: evolve TextField, TextEditor and DropDownList to use the shared presentation without changing their native editing/popup responsibilities.
  5. Domain wrappers: keep IP, prefix, DNS, secret and numeric semantics in their appropriate modules. Rich validation may return state, messageKey and tokenIndex; generic rendering must not parse IPs or know daemon APIs.
  6. Identity and commands: preserve existing objectName/focusKey on the actual editable target. Wrappers must not create duplicate targets or break typed DetailsNavigation discovery. Embedded actions retain shared Alt commands/content-menu routes, not new field Tab stops.

Validation must not silently rewrite traversal

Preserve the current Enter/Tab/Escape contract. In Wi-Fi, Enter/Tab can retain the value in the existing domain draft while IpSettingsState.ready() prevents an invalid/incomplete group from reaching the backend. Show the inline error without stealing focus or trapping Tab. Escape discards the active field edit and reveals the latest source/domain draft; it does not undo an already submitted operation.

Do not install a generic “invalid field cannot lose focus” policy. Other domains keep their existing rejection/retry ownership. Any change to save-result semantics must be a separate interaction-contract change with tests, not hidden in this visual refactor.

Hard constraints

No hover tooltips, floating help labels, F1 overlays, per-field keyboard navigation variants, hidden backend writes or credential retention. Modal required-input dialogs keep their native contained traversal and explicit submit/cancel exception. Display layout still requires Preview and Keep/Revert. The Power chart remains pointer-entry-only.

08 / Commit-sized implementation sequence

Prototype once, then migrate by risk.

  1. Approve the visual decisions

    Confirm filled default, 12px shape, 56/48px densities, 16px input, persistent adjacent labels and readonly treatment. Compare real Qt light/dark samples before treating the diagrams as final tokens. Commit the agreed specification.

  2. Build shared presentation

    Add form tokens and passive composition. Restyle FieldFrame/TextField/DropDownList behind the explicit form variant; leave search unchanged. Test label forwarding, slots, pending/error and focus boundaries. One commit.

  3. Complete multiline parity

    Give TextEditor the shared presentation contract without replacing its native editor or lease hooks. Verify nested scrolling, text selection, IME, saved caret and draft recovery. One commit.

  4. Migrate representative simple fields

    Bluetooth names, Display Focus numbers and one choice page. Remove duplicate external labels, ad-hoc heights and typography overrides; preserve stable focus keys and acknowledgements. Commit each coherent surface slice.

  5. Migrate IP/DNS carefully

    Reuse the existing parser, add field-specific validation explanations, address/prefix layout and safe paste-buffer handling. Integrate the DNS text area through shared transactions. No automatic CIDR split. A separate tested commit.

  6. Migrate prompts and inline editors

    Wi-Fi credentials, Bluetooth pairing, QR readonly values, notification reply, todo add and Clipboard. Preserve sensitive closure, send/submit ownership and failed drafts. Commit separately where recovery policies differ.

  7. Remove transitional styling

    After every consumer migrates, remove local 34/38/40px field overrides and obsolete aliases. Keep only approved normal/compact/textarea variants. Update the component gallery and current visual documentation. One cleanup commit.

  8. Accept the real system

    Run the full checks and live keyboard/IME/screen-reader/theme/geometry journeys. Inspect dense forms and toasts at normal and larger text. Record unresolved limitations rather than claiming native Material conformance.

Primary migration inventory: BluetoothDeviceActions.qml, BluetoothAdapterSettings.qml, DisplayFocusSetting.qml, AdvancedIpSettingsPane.qml, AdvancedSecurityPane.qml, WifiCredentialDialog.qml, PromptDialog.qml, NotificationReplyRow.qml, ActivityTodoSection.qml, ClipboardDetailCards.qml. Selector consumers migrate with their form region, not independently by convenience.

09 / Definition of done

A coherent family is behavioral as well as visual.

Automated boundaries

  • Real Qt Tab/Shift+Tab wrapping, browse/edit distinction, Enter save, Escape discard and local drafts. No setting writes while merely typing.
  • Search dimensions, caret, IME, result navigation and query restoration unchanged.
  • Native label/name association, required/read-only state, accessible reveal/clear actions and no empty/generic “Required” names.
  • State combinations: invalid + editing, pending + focus, readonly + selectable text, disabled + meaningful error.
  • Rendered-pixel contrast in both themes and multiple seeds: ≥4.5:1 normal text and ≥3:1 meaningful indicators/focus cues against adjacent colors. Recheck actual fill/tint composites after moving to Container Highest; disabled controls are a separate state, not a license to dim read-only values.
  • IP matrix above, clipboard/full-string paste, middle-click paste where supported, duplicate delimiters, long IPv6/DNS, mode changes and backend rejection.
  • Secret reveal/hide/close, domain draft retry/discard, delayed acknowledgement, no focus-restoration side effects.

Visual and live acceptance

  • Normal and 48px compact contexts; 320/480px form content; current supported split geometry; 125/150/200% scale and larger text.
  • All labels and error messages readable; slots never overlap text; no accidental mobile-size reduction or clipped trailing controls.
  • At least one keyboard-only journey through each migrated domain and each required-input dialog.
  • Actual hardware IME and screen-reader announcements for labels, units, invalid state, pending operations and interactive icons.
  • Native text selection/copy, popup focus restoration, touch/trackpad behavior and reduced-motion end states.
  • Screen-reader alert behavior checked with supported Qt APIs; no announcement storm on each incomplete keystroke.
  • Power chart remains outside keyboard entry and command discovery.

Implementation gates: tests/run-qmllint.sh, tests/run-qml-tests.sh, tests/run-runtime-smoke.sh, tests/check-ip-validation.js with its validator argument, tests/check-material-colors.js with the generated bundle, and the current sibling-aware quality gate. These are future implementation gates, not checks claimed for this documentation-only proposal. Add/extend representative interaction tests rather than substituting static screenshots for behavior.

Decisions requested before implementation

  1. Approve filled Container Highest + 12px all-round corners as the default form style.
  2. Approve 56px normal / 48px explicit compact, keeping 16px input text; review the increased vertical budget.
  3. Approve persistent external labels, no floating labels, and a shared conditional/reserved supporting row.
  4. Approve normal-contrast readonly values with meaningful automatic/read-only state.
  5. Approve one native IP editor, separate prefix and one DNS list editor; defer automatic CIDR splitting and chip-based lists.
  6. Approve neutral intermediate input, errors on explicit save, without changing Tab traversal or backend readiness guards.
