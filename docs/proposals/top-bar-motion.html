01

The center capsule

A small, independent media landmark at screen center. It opens sideways without disturbing either edge.

Recommended / best balance
Hover to peek. Click the chevron to keep it open.

120ms pointer intent → 180ms expansion → 350ms leave grace

Resting · controls tucked away
Artwork + indicator + chevron→Previous · Pause · Next→Same small anchor

Placement

True screen center, not the center of leftover space. Workspace changes never push it around. Both sides expand evenly; the centerline stays fixed.

Reveal policy

Hover reveals after a brief intent delay. The chevron is the explicit click/touch/keyboard route and holds controls open. Escape closes. Focus inside prevents automatic hiding.

Tradeoff

The expanding buttons move during entry. Keep movement short, and never auto-collapse while a control has focus. At narrow widths, retain the opener and route to Media instead of colliding with edge groups.

02

The inward drawer

Media joins the system side, not the workspace side. A deliberate click unfolds transport into the empty middle.

Most predictable / no hover magic

Explicit reveal → 180ms inward expansion → explicit dismissal

Placement

Immediately before the system cluster. The artwork and reveal button are right-anchored. Only the drawer’s left boundary changes; Wi-Fi, notifications and the clock never move.

Reveal policy

No hover-driven opening. Click toggles, Escape dismisses, and a click outside dismisses. Playback changes do not expand or collapse it. It stays open while you’re using it.

Tradeoff

A second gesture is needed before transport. In return, there are no accidental fly-outs while crossing the bar. A good default if you prefer predictable, deliberate interaction over maximum immediacy.

03

The drop shelf

Keep the bar physically unchanged. Reveal a tiny media shelf below it, only when requested.

Placement

Transport sits below the bar, not inside it. The opener remains centered while workspaces and system status keep their own edges. The shelf is intentionally small: no duplicated track inspector.

Reveal policy

Explicit click only; never a hover trap. Fade in while settling down 6px, without scaling the icons. Click outside or Escape closes. Opening does not start playback or change the selected player.

Tradeoff

It temporarily overlaps application content and needs a real transient input region. Prefer this if visual calm matters most; avoid it if you strongly prefer every control to stay inside the reserved bar area.

The direction I’d take

Independent center.
Motion with a purpose.

Start with 01. It makes media genuinely independent, gives an ultrawide bar a useful center landmark, and offers quick transport without permanently displaying every control.

Use 02 if hover disclosure feels too eager. Choose 03 if you want a completely stable bar footprint. Don’t combine all three: one reveal grammar will feel more intentional than several competing tricks.

The main change from round one is architectural: placement follows purpose, not the existing item order. These are proposals for approval, not silent changes to the current contract.

Small motion. Firm boundaries.

01 / Only reveal secondary controls

Keep workspaces, time, important status and the media opener visible. No hiding low battery, urgent notifications or errors. No full-bar auto-hide in this round.

02 / Nothing moves just because music plays

No automatic expansion on track change. No bouncing artwork, pulsing play button, marquee title or perpetual waveform. Playback state uses a static, acknowledged icon.

03 / Hidden means non-interactive

Hidden transport has no pointer or keyboard targets. Focus must never be left in disappearing content. Animations don’t invoke actions; the artwork never doubles as Play.

04 / Reduce motion, not access

The Motion Off setting and OS reduced-motion preference remove transitions entirely. The same controls, triggers, dismissal rules and readable states remain.

05 / No player ≠ no way in

Keep the neutral Media opener available. Collapse and disable transport disclosure, retaining the affordance’s geometry. Player arrival does not auto-expand the controls.

06 / Overflow is not an animation

Reserve space for the largest open state. When there isn’t room, keep an opener-only density and use the existing Media chooser. Never cover workspaces or shrink targets to force a fit.

Implementation notes & acceptance checks

Only an HTML proposal has been added. No QML, daemon behavior, panel navigation or current contract is changed. The current interaction contract remains authoritative until an approved design is implemented.

  • These concepts intentionally propose moving Media out of the existing workspace-adjacent order. Disclosure is a separate action from opening the existing Media chooser. Artwork, transport and padding retain distinct hit regions; opening/closing must never pin a player, play, seek or write a preference.
  • Keep the existing media selection and capability rules. The demo is a music fixture with Previous/Next; production keeps the existing track-versus-seek policy and independent action guards. The shelf is a bar transport extension, not a new editable panel.
  • Use shared action controls and existing native keyboard routes; assign disclosure a non-conflicting named command if required. Do not put native bar actions into panel field Tab traversal. The web prototype uses conventional Tab and Enter/Space solely for browser accessibility.
  • Review bar/BarContent.qml, bar/MediaChip.qml and the bar/popup host geometry. Keep the existing exclusive zone unchanged. Hidden or transparent areas must not consume desktop input; the shelf should not reflow windows.
  • For 01/02, compute collision bounds from the real widths of workspaces, status, date, translations and the fully opened media group. Re-evaluate on output/density changes. This board uses a scrollable 1040px minimum review canvas, not a production narrow-screen implementation.
  • Add real Qt tests for hover cancellation, close/reopen reversal, focus retained during pointer departure, Escape restoration, disabled transport, player disappearance, output resize, reduced motion, and no actions on disclosure. Verify live compositor input masks and 3440 / 1200 / 700 / 300px layouts before shipping.
  • Any approved behavior change must update the contract documentation with its actual native command and focus model. Preserve all existing panel save/discard and backend acknowledgement guards.
