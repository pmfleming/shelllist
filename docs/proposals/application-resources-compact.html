Static visual proposal, not live telemetry. CPU, GPU, RAM, GPU memory and zero app-data values borrow from your screenshot; all traces, traffic, power, timestamps and coverage are synthetic. The traces represent the selected history window, not an invented timestamp for the latest snapshot. The app header is context only; its existing commands and footer tabs remain unchanged.

01 / MERGE THE REPETITION

Snapshot + trend = one row.

Remove “Known disk data…”, “Using right now”, “Data moved” and the separate “Resource history” section. The values already answer those questions. A resource name appears just once.

02 / USE FIVE GRAPH FORMS

Different shapes, useful reasons.

Lines compare activity. Steps show held memory. Columns reveal I/O bursts. Diverging areas separate network directions. A power area connects rate with accumulated energy.

03 / ICONS, NOT GUESSWORK

Shorten labels, keep units.

Replace “Disk read”, “Network receive” and “Power now” repetition with direction glyphs and W. Keep CPU, GPU, RAM and short resource headings: a mystery chip icon is not enough.

read / receivewrite / send◷ observed time≈ estimated total
04 / DISCLOSE, DON’T DELETE

Move the explanation down a layer.

Average, peak, swap, allocation and attribution method belong in Measurement details. Missing-data reasons, RSS fallback, energy source/confidence and installation scope stay visible when relevant.

05 / KEEP THE TIME ALIGNMENT

No tiny dashboard tiles by default.

A full-width strip gives every chart the same start, end and plot position. It is easier to correlate a CPU burst with disk or power than in a two-column mosaic.

What actually saves height: remove the duplicated overview/history architecture, nested card padding and repeated prose. Keep plots about 45–54 px high; do not solve density by shrinking text to illegibility. At narrow widths or larger text sizes, values and plots wrap and the page scrolls.

Snapshot details

  • RAM source: RSS fallback. Swap: 0 B. Retained memory source: not recorded.
  • GPU resident: 246 MiB. Allocated: 246 MiB. Neither is added to RAM; allocation is not a capacity denominator.
  • App data: persistent 0 B; temporary 0 B. Referenced files: 0 B, of which temporary 0 B. Referenced files are separate overlapping/shared observations.
  • Installation and shared dependencies: not measured. Memory bandwidth: not measured.

Measurement details

  • Expose the actual attribution method, process coverage, sampling interval and shared-attribution warning. Do not turn sampling interval into snapshot age.
  • Time-weighted means and ≈ totals cover observed intervals only. Missing or mismatched canonical summaries give unavailable estimates, not extrapolated totals.
  • Energy estimates attribute measured CPU-package energy. Period confidence is the weakest known confidence over valid retained samples, or unknown.
  • Historical timestamps and sample counts remain available. A stopped app shows a timestamped last observation, not “Latest snapshot”.

05 / implementation boundaries

Dense, not delicate.

This is a proposal only. It intentionally changes the default visibility of average/peak values; approval should precede updating the existing resource contract.

Layout and chart rules

  • Five horizontal groups, not five nested card stacks. Use roughly 10–12 px inner padding and 7–8 px gaps. Target 640–720 logical px for the resource body including metadata, excluding the existing app header and tab footer.
  • 45–54 px plots with aligned left/right edges. Keep one selected time window and one bottom time axis with actual timestamps. Reflow at narrow widths; allow vertical scrolling and font scaling rather than clipping labels.
  • Scales always visible. Activity uses one labeled adaptive percentage axis; memory one byte axis; disk and network separate symmetric rate axes. No dual-axis overlay of W with %, or MiB with B/s.
  • Stepped memory needs honest intervals. Draw retained bucket values over their known duration, not a claim of exact allocation-change timing. Do not carry values across an unobserved boundary.
  • Columns must respect bucket width. Disk columns encode observed-duration bucket means; do not make sparse irregular samples look like equal continuous coverage. Downsample by duration, without erasing gaps.
  • No decorative smoothing. Preserve real spikes and discontinuities. Use solid/dashed strokes and upper/lower position, not color alone, to distinguish traces.

Interaction, accessibility and correctness

  • Shared keyboard workflow unchanged. The 30m / 2h / 24h shared segmented control stays the only editable stop. Enter saves; Escape discards; Tab saves and continues editing. Arrows do not traverse fields.
  • Details are a command, not another field. Propose an icon-only shared information command with Alt+H, subject to existing scope/collision guards and a full named-menu entry. It reveals a read-only section; PageUp/PageDown scroll it. No hover-only explanation or new chart inspection shortcut.
  • Icons keep full accessible names. Read “Network receive, 24 kilobytes per second”, not “down arrow 24”. Announce scale, current value, mean, peak, coverage and missing-data reasons in static accessible summaries, even when visual stats are collapsed.
  • Keep validation and attribution gates. Finite nonnegative readings plus the relevant capability; network connections do not establish byte attribution. Energy source must remain RAPL. Per-series gaps and process coverage remain distinct.
  • New GPU memory trace is conditional. The current page already reads resident/allocated GPU memory values, but does not chart their history. Verify retention and canonical summary support before enabling the proposed resident trace. Fall back to RAM history plus the existing GPU snapshot; no new collector is assumed.
  • Not new application behavior yet. Browser disclosure controls here are for reviewing this document. No QML, backend, keyboard contract or existing approved proposal has been changed.
Implementation sequence and acceptance checks

Suggested sequence

  • First unify overview values and existing history into five groups, without changing calculations.
  • Then add chart styles to shared resource rendering: paired lines, steps and interval columns, with deterministic gap handling.
  • Reuse the canonical observed-duration summaries for means, peaks, totals and coverage. Avoid deriving totals from the displayed/downsampled trace.
  • Move verbose labels and methodology to read-only details; add the shared information command and accessible summaries.
  • After approval, update docs/application-resources.md and the Resources section of the keyboard contract to describe the read-only disclosure command.

Acceptance before shipping

  • Actual Qt key/pointer tests: sole editable range field, draft/save/discard, forward/reverse wrap, information command, command menu and scroll behavior.
  • Geometry at 360, 540, 680 and 900 logical px widths, plus fractional scaling and large text. No overlap, clipped values or newly introduced Tab stops.
  • Zero, invalid, missing, stopped, loading, partial-direction availability, unequal coverage and unknown confidence cases.
  • Render tests for shared axis alignment, per-series gaps, step/column bucket boundaries and no interpolation over unsupported buckets.
  • Canonical window/weighting checks and period estimates unchanged. GPU resident history gracefully falls back if not supported.
  • Measure real content height and readability against the current Qt page; the mockup’s height budget is not a benchmark.
Alternatives considered: a two-column tile grid is shorter, but loses the strongest time alignment and wraps awkwardly in the narrow details pane. CPU/GPU gauges provide variety but consume space and discard history. RAM/VRAM donuts imply a capacity denominator the app does not provide. Stacking RAM + VRAM, adding referenced files to app data, or overlaying power on CPU with a hidden second scale would be misleading. Prefer the compact strips.

Not just a font-size problem.

The screenshot repeats disk and RAM values before their own cards. “Space on disk” nests a large tinted value card inside another card and repeats scope caveats. Four usage cards reserve most of their height for labels and explanations.

The source adds two energy cards and four I/O cards, then repeats current values inside history beside average, peak and observation sentences.
