01 / Review

One decision. Too many explanations.

01 — Content

The mapping is repeated

The introductory paragraph, “Category & default workspace” title, every option, and the footer all explain the same relationship. “Code · Workspace 3” adds bookkeeping, not a useful choice.

02 — Hierarchy

The wrapper competes with the field

A card around one selector adds another layer without grouping anything. Keep a persistent label, one filled field, and useful supporting text. Save the strong accent edge for editing.

03 — Usefulness

Show the effect, not the mechanism

Answer the practical questions: which category is saved, what happens to new windows, and do existing windows move? Keep unassigned, pending, and rejected changes honest.

Recommendation: rename the field Workspace category. Keep only Shell, Browser, Code, Media, Text in the menu. Explain the launch behavior once; remove workspace numbers from normal UI.

02 / Recommended design

Less chrome. More confidence.

Same shared dropdown, cleaner composition. These are static design mockups, not functioning Qt controls. The theme button changes all examples.

The keyboard legend belongs to this review, not an extra permanent footer in the panel. The open-menu frame is taller only to show its popup; do not enlarge the production panel or reserve a blank menu-sized area.

03 / Useful states

A request is not a saved setting.

Keep the acknowledged value visible until the backend confirms a change. Put transient status immediately below the field, in place of its category description.

Handle a mismatched mapping separately. The current code treats a category/workspace mismatch as no selection. Do not label that “unassigned.” Use “Category mapping needs attention. Choose a category to update it,” and suppress the normal launch-effect claim until the acknowledged mapping is valid. Keep raw IDs in diagnostics, not every menu row.

04 / Material 3 alignment

Use the existing design system, not a new skin.

56px filled field height
48px menu row height
16 / 24px value type / line height
12px field & popup corners

Material-derived improvements

  • Tonal hierarchy: Surface Container panel, Surface Container Highest field, and a raised menu. Avoid border-on-border containment.
  • Typography: 14px persistent label, 16px value/options, 12px supporting text. Use On Surface and On Surface Variant, not arbitrary dimmed white.
  • Selection: a secondary-container saved row with a check; a separate accent treatment for the active edit. Color is not the sole cue.
  • Icon consistency: packaged Material Symbols in production, not embedded Nerd Font characters in labels. These offline illustrations use inline SVG approximations.

Deliberate Shelllist adaptations

  • Not a claim of stock M3 conformance: external labels, 12px all-round field corners, and the browse pill are established product choices.
  • No keyboard redesign: only editable controls are field Tab stops. Arrows browse results outside editing; inside the menu they select options.
  • No new settings: five fixed choices do not need search, a five-wide segmented control, or a separate workspace selector.
  • Theme-aware: illustrative blue palettes here; production must use the existing seed-derived semantic tokens, never these hard-coded swatches.
05 / Implementation handoff

A small change with clear boundaries.

Composition & copy

  • In launcher/ApplicationSettingsPage.qml, replace the long introductory paragraph and single-control card with a shared Ui.FormField + Ui.DropDownList. Retain navigation boundaries and stable applicationCategory identity.
  • Use Workspace category for the visible and accessible name. Set option labels to category.label only. Workspace IDs remain internal payload data.
  • Keep ApplicationPreferences.js as the source of labels and useful category descriptions. Render icons through shared icon support, not a panel-local menu.
  • Use one supporting/status slot and one passive consequence block. Do not duplicate a global failure verbatim beside the field.

Behavior & acceptance

  • Preserve onSelected, settingsInFlight, backend validation, error ownership, and acknowledgement. If saved-check versus draft styling needs work, improve the shared dropdown.
  • Enter saves; Escape discards; Tab/Shift+Tab saves and continues editing. Pointer entry follows the same transaction. Blur and panel closure do not save.
  • Add actual Qt interaction coverage for category-only labels, forward/reverse traversal, cancel/no write, pending/rejection, acknowledged values, and mismatched mappings.
  • Check narrow panels, translated labels, light/dark contrast, popup clipping, and accessible announcements. Document this composition without introducing a panel-specific key model.

Basis: Shelllist interaction contract · Material visual foundation · M3 text fields · M3 menus. This proposal is based on the repository’s documented M3 foundation, not a new external conformance audit.
