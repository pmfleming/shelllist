What I’d change from your screenshot

Clarity first. Expressiveness second.

01 / IDENTITY

“Chrome” isn’t what you’re listening to.

Lead with the show, book or artist. Put the recognizable service icon beside it and “Pocket Casts · via Chrome” underneath. Keep the full episode or track title in the playback card. Don’t repeat the same artist and album text.

02 / HIERARCHY

Artwork is an anchor, not a wallpaper.

The current enlarged crop loses the cover and needs a heavy text scrim. Use contained square artwork, a legible tonal surface, larger content type and generous spacing. Keep the circular primary action in the shared header.

03 / UTILITY

Show where I am, not just “paused”.

Add elapsed time, remaining time and a progress track. Use seek for spoken audio, track navigation for music, and move extra actions into More. Use pause/equalizer icons for state and numbers for elapsed time, remaining time and speed. Remove persistent navigation tips, transport captions and progress explanations; keep full meanings in accessible names.

The important part underneath

Recognize the service. Keep the real session.

A presentation resolver should return service, icon, content kind and evidence—without replacing the MPRIS player ID used for controls, pinning or acknowledgement.

Proposed resolver · not implemented

1. Explicit app identity

Resolve a known desktop_entry, exact normalized MPRIS identity or registered PWA app ID. Prefer installed app/theme assets; provide bundled, reviewed service icons for web sessions. Don’t mistake a Chrome icon for a Pocket Casts icon.

2. Trusted web origin

When exposed, match a verified page origin: play.pocketcasts.com, open.spotify.com, or an explicit Audible regional/player-host allowlist. Parse URLs and enforce host boundaries. A CDN media URL or album-art URL is not proof of the service.

3. Honest fallback

Chrome often reports only “Chrome”. If no trusted origin or mapped app identity exists, use the content title and browser icon. Don’t guess from “The Anfield Wrap” or “The Rigor of Angels”. Offer an explicit app-scoped override only where a stable app identity exists.

A practical implementation plan

Keep this a shared-surface improvement, not a bespoke player UI.

Available now / mostly presentation work

  • Replace the identity-only heading in bar/SystemChooserContent.qml. Normalize duplicate artist/album labels.
  • Update bar/SystemEntries.js to use resolved service labels/icons and include them in search text.
  • Rework bar/MediaPlaybackCard.qml with contained artwork, state icons and a read-only numeric timeline. The contract fixture already exposes position_us, length_us, playback_rate and observation time.
  • Use existing BarMediaPresentation policy for track vs seek controls. Honor every capability and in-flight guard. Render remaining time as media duration, not an unqualified wall-clock estimate.

Needs explicit data / interaction work

  • The current fixture has no trusted page origin. Browser recognition needs an upstream metadata contract or known PWA mapping; presentation-only code cannot recover missing identity reliably.
  • Keep content classification separate from service recognition. Do not classify every Spotify session as music.
  • Scrubbing, output-device routing, chapter navigation, speed editing and sleep timers are not promised by this mockup. Add only with corresponding backend operations and safety tests.
  • Clamp progress, stop extrapolation while paused, rebase from acknowledged observations and handle missing/stale data. Preserve selected-session identity across updates.

Material / Pixel-inspired, not a claimed replica

Use the project’s HCT-generated M3 color roles, Roboto Flex and Material Symbols Rounded in production. This offline mockup uses illustrative tonal pairs and inline SVGs. A neutral container, restrained artwork-derived accent, 28/24/20px nesting and expressive progress styling provide the Pixel direction without recoloring every surface. The wave is a playback indicator, never a fake audio waveform; use a static track when paused or reduced motion is requested. Keep theme seed as fallback if artwork extraction fails.

Keep Shelllist’s keyboard contract

Reuse ProviderChooserSurface, SurfaceActionRow and shared fields. Header primary 56px, secondary circles 32px. Arrow keys browse results; Tab visits only editable preferences; Enter edits/saves; Escape discards; Tab saves and continues. Actions stay on Alt+letter, with hints shown only while Alt is held—no persistent shortcut footer or hover tooltips. Artwork and this read-only timeline remain information-only. Add actual Qt interaction, capability, icon-fallback and identity-isolation tests before shipping; no interaction contract is changed by this proposal.

Icon-first, not explanation-first

Keep titles, creators, service identity and concise setting labels as text. Use pause/equalizer icons for session state; seek arrows already contain “30”. Show timing as 24:18 / −41:02 and reported speed as 1×, without “remaining”, “progress” or “speed” captions. No browsing reassurance, status sentences, duplicate transport labels or keyboard legend in the player. The pin switch needs only “Pin to bar”; automatic control policy is illustrated by its transport icons. Browsing still never pins or switches the bar player.

Retain full accessible names, named command menus and modifier-held hints. Timing accessibility labels identify episode, track or reported-segment scope; never invent a chapter or whole-book total. Use —:— for missing timing and omit unreported rate. Important errors, validation and recovery guidance remain readable text: don’t replace ambiguous or safety-critical meaning with an unexplained icon.

Design proposal only. Service marks are illustrative SVG stand-ins; ship approved brand assets, not redrawn logos. All artwork and timing values are sample compositions, not fetched media. References: Material 3 and Google’s M3 Expressive direction. Pixel-inspired, not a verified reproduction of the latest Android build.
