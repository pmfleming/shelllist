P1 · Keyboard reachabilityReproduced in Qt

The chart has an inspector.
The keyboard cannot enter it.

Battery history still supports native Enter/Right inspection and Left/Right sample movement. But the shared panel intercepts Tab and discovers only registered editors and scrolling pages. The graph is neither a registered editor nor an action command.

What the probe established

Twelve Tab presses never reached the graph. It was absent from both navigation targets and content commands. Explicitly giving it native focus and pressing Enter did start inspection.

Why it matters

After hover values were removed, exact historical measurements were meant to remain explicitly accessible. That route is now pointer-dependent, contrary to the keyboard-first plan.

Next change

Add an explicit inspection command through shared command navigation, with a supported inspection boundary and focus restoration. Test keyboard-only entry, sample movement, Escape and return to the prior field. Do not make all read-only charts field Tab stops or create a new panel-local editing model.

P2 · Browse-focus contrastCalculated + illustrated

Immediate focus is not
the same as distinguishable focus.

Browse focus adds an 8% Primary tint, without an edge. A selected result keeps its selection fill and avatar when focus moves elsewhere, so that small tint is its principal added keyboard-focus cue. Editing has a stronger accent edge, but that does not fix browsing.

Why the existing test still passes: the palette gate compares opaque Primary against surfaces. The UI paints a low-alpha composite instead. All 150 palette combinations pass; this is a rendered-state coverage gap, not a failure of Material Color Utilities.

Next change

Agree and test a distinguishable, immediate tonal browse treatment for selected rows and controls. Preserve control-only highlighting. Do not silently restore the rejected heavy rectangular focus ring. Validate the layered colors actually painted, not just their source tokens.

Delivered ≠ accepted in every state

What is a gap—and what is still a proposal?

The October 1 mockups are not ten mandatory unfinished requirements. Later decisions supersede parts of them. In particular, footer counts, icon-only detail tabs and the new single-row action hierarchy are intentional.

Surface-by-surface follow-through

Do not re-open fixed September findings as if they describe the current implementation.

Prioritize chart keyboard entry and custom card containment. The old profile-selector and truncated safety-warning defects should not be repeated.

Applications / Clipboard

Fix destructive-icon contrast; migrate Applications resource cards. Preserve editor drafts, retry and resource content.

Displays

Current categories and arrangement work supersede the old long-form snapshot. Preserve local drafts, explicit Preview and Keep/Revert. No new display defect was established here.

Notifications

Current inspector and selected-message commands differ from the old hover-action row. Do not repeat its historical invisible-action reproduction. Live toast interaction/accessibility remains open.

Wi-Fi / Bluetooth

Shared fields, prompts and acknowledgement are the baseline. No new domain-specific Material defect was established. Always-visible technical sections are now intentional.

Activity / Time & Weather

Prior naming/hero fixes are recorded as delivered. Large-text chart/forecast and small supporting-type acceptance remain.

Audio / Media / Tray

Acknowledged volume steps, now-playing hierarchy, supplied tray icons and dedicated routes exist. Do not invent an absolute-volume setter or routing API as a styling fix.
